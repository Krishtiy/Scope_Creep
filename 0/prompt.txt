ok this is the implementation plan that i have for the builidng the project presistance , gothrough it and tell me can we integrate this?# Project Persistence (Save & Reload): Implementation Plan

Feature plan for **Scope-Creep Catcher**, built for the Hacktoberfest Open-Source AI Challenge (Week 2: Side Hustle).

**Time-box:** about 4 to 5 hours total. Deadline is Sun Oct 18, 11:59 PM PDT (about 12:29 PM IST on Mon Oct 19), and the gold eval, demo video, first user and DEV post still matter more for the score. If time runs short, cut from the "Cut list" at the bottom, never the tests.

> **Note:** this plan was written without seeing `engine/state.py` or `app.py`. The progress report says `state.py` already has persistence and tests, so **Step 0 is an audit** to find out what is really missing. Only build the gaps.

---

## 1. Goal

When you create a project (for example `apex-fitness`):

1. It is saved to `data/projects/apex-fitness.json`.
2. After a browser reload (F5) or after stopping and restarting the app, you can reopen that project with its **saved SOW, stress-test cards, client-request decisions, log and revision quota intact**.

**Why this matters for the challenge**
- Supports "data stays on your machine": everything is local JSON, works with Wi-Fi off.
- Needed for the first-user session, so they can come back to their project.
- Technical Execution: atomic saves, validation, migration and tests.

---

## 2. Step 0: Audit (30 min)

Read your code and one existing `data/projects/*.json` file, then answer:

1. Does `app.py` save after every state-changing action, or only some?
2. Is there an "open existing project" control, or does the sidebar only create new projects?
3. What does a real saved file contain? Define schema v1 from that file, not from this plan.
4. Are derived values (top-bar totals) saved? They should be recomputed on load instead.

Why this matters: a browser refresh creates a **new Streamlit session**, so `st.session_state` is gone. The saved file is the only thing that survives, so a project list and a "last opened" memory are probably the missing pieces.

---

## 3. What gets saved (schema v1)

| Field | Notes |
|---|---|
| `schema_version`, `project_id` (slug), `name`, `created_at`, `updated_at` | Version allows migrating old files |
| `settings` | Hourly rate, currency, contract price, niche profile |
| `sow_text`, `sow_hash`, `sow` | Extracted facts, including any manual edits |
| `stress` | Missing (M) and vague (A) cards with status |
| `quota` | Raw `revisions_used` counter |
| `checks` | Each client message with its decisions: final verdict, rule ids, both quotes, quote methods, hours, price, model name, `sow_hash` at the time, optional draft text |
| `log` | Entries with status Pending / Approved / Declined |

Rules:
- Give every check and log entry a short id.
- **Do not save derived values** (top-bar totals, percentages). Recompute them from the log on load.
- Match the type names to your existing `state.py` models.

## 4. Step 1: Core save and load (pure Python, about 1.5h)

Add to `engine/state.py`:

```python
import re, json, os, shutil, tempfile, unicodedata
from pathlib import Path

DATA_DIR = Path(os.getenv("SCC_DATA_DIR", "data/projects"))   # tests override this
SLUG_RE = re.compile(r"^[a-z0-9][a-z0-9-]{0,62}$")
RESERVED = {"con", "prn", "aux", "nul", "com1", "lpt1"}       # Windows reserved names

def slugify(name: str) -> str:
    s = unicodedata.normalize("NFKD", name).encode("ascii", "ignore").decode().lower()
    s = re.sub(r"[^a-z0-9]+", "-", s).strip("-")[:63].strip("-")
    return "untitled" if not s else (f"{s}-project" if s in RESERVED else s)

def project_path(slug: str) -> Path:
    if not SLUG_RE.match(slug):
        raise ValueError("bad project id")
    p = (DATA_DIR / f"{slug}.json").resolve()
    if p.parent != DATA_DIR.resolve():
        raise ValueError("bad path")
    return p

def save_project(state) -> None:
    state.updated_at = now_iso()
    path = project_path(state.project_id)
    text = json.dumps(state.model_dump(mode="json"), indent=2, ensure_ascii=False)
    DATA_DIR.mkdir(parents=True, exist_ok=True)
    fd, tmp = tempfile.mkstemp(dir=DATA_DIR, suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            f.write(text); f.flush(); os.fsync(f.fileno())
        if path.exists():
            shutil.copy2(path, path.with_suffix(".json.bak"))   # keep one backup
        os.replace(tmp, path)                                    # atomic swap
    except Exception:
        if os.path.exists(tmp):
            os.remove(tmp)
        raise

class ProjectLoadError(Exception): ...

def load_project(slug: str):
    path = project_path(slug)
    try:
        raw = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError) as e:
        raise ProjectLoadError(f"Could not read {path.name}: {e}") from e
    try:
        # ProjectState uses extra="ignore"; missing fields get defaults
        return ProjectState.model_validate(migrate(raw))
    except ValidationError as e:
        raise ProjectLoadError(f"{path.name} has an unexpected format") from e

def list_projects() -> list[dict]:
    """Return name, slug, updated_at for each *.json. Mark unreadable files, never crash."""
```

Design reasons:
- **Temp file then `os.replace`:** a crash mid-write cannot leave a half-written JSON file.
- **`encoding="utf-8"` and `ensure_ascii=False`:** the default encoding on Windows can break smart quotes or the ₹ symbol.
- **Strict slug and path check:** a project name like `../../x` cannot write outside the folder.
- **Never overwrite a file that failed to load.** Show an error and offer the `.bak` copy.
- **`migrate()`:** treat a missing `schema_version` as 0 so your existing files still load.
- **Name collisions:** if the slug exists, say "already exists, open it or pick another name". Never overwrite silently.

## 5. Step 2: Wire it into Streamlit (about 1.5h)

### 5.1 One source of truth
Keep a single `st.session_state.project` object. Widgets update it through callbacks. If `app.py` currently uses many loose keys (`sow_text`, `rate`, and so on), consolidate them first.

### 5.2 Save only when something changed
Streamlit reruns the whole script on every click, so do not save blindly.

```python
import hashlib
from datetime import datetime

def persist_if_changed():
    p = st.session_state.get("project")
    if not p:
        return
    snap = hashlib.sha256(p.model_dump_json(exclude={"updated_at"}).encode()).hexdigest()
    if snap != st.session_state.get("_saved_hash"):
        save_project(p)
        st.session_state["_saved_hash"] = snap
        st.session_state["_saved_at"] = datetime.now().strftime("%H:%M:%S")

# call persist_if_changed() at the very end of app.py
```

### 5.3 Open a project without stale leftovers
```python
def open_project(slug):
    p = load_project(slug)
    for k in list(st.session_state.keys()):            # clear the previous project's leftovers
        if k.startswith(("reply_area_", "draft", "client_msg", "last_check")):
            del st.session_state[k]
    st.session_state.project = p
    st.session_state._saved_hash = hash_of(p)
    st.session_state["sb_rate"] = p.settings.hourly_rate   # set widget keys BEFORE widgets render
    st.query_params["project"] = p.project_id
    (DATA_DIR / ".last_opened").write_text(p.project_id, encoding="utf-8")
```

Streamlit gotcha: a widget that already has a `key` ignores a new `value=`. Set `st.session_state[key]` before the widget is created, or do it inside a callback.

### 5.4 On startup
1. Read `st.query_params.get("project")`, else the `.last_opened` file.
2. If that project file exists, call `open_project` inside `try/except ProjectLoadError`.
3. A bad file shows an error in the sidebar and the app keeps running.
4. Check that your Streamlit version supports `st.query_params`.

### 5.5 Sidebar "Project" block (top of sidebar)
- Dropdown of existing projects, for example "Apex Fitness, updated 14:03"
- "New project" name box with a Create button (uses `slugify`, handles collisions)
- Caption: `Saved to data/projects/<slug>.json, last saved HH:MM:SS`. This is also good evidence in the demo video.

### 5.6 On load
- **Do not re-run the model.** Show stress cards and decisions from stored data.
- Optional cheap integrity check: re-verify stored quotes against the stored SOW with `verify_quote` (no LLM needed).
- **Stale-analysis banner (P1):** if the SOW text changes, its hash no longer matches saved analyses. Show "this analysis is from an older SOW, re-run" and do not delete anything.

## 6. Step 3: Automated tests (about 1.5h)

Use `tmp_path` and `SCC_DATA_DIR` so tests never touch real project data.

- [ ] `slugify`: spaces, capitals, symbols, empty string, non-English text, Windows reserved names
- [ ] Path traversal such as `../../etc/x` is rejected
- [ ] Saving creates `<slug>.json` that is valid UTF-8 JSON
- [ ] **Round trip:** save then load gives equal SOW facts, stress cards, quota, checks (verdict, rule ids, quote methods) and log
- [ ] Smart quotes, `₹` and emoji survive the round trip
- [ ] Atomic write: monkeypatch `os.replace` to raise, then the original file is unchanged and no `.tmp` is left behind
- [ ] Corrupt file raises `ProjectLoadError`, and `list_projects` still returns the other projects
- [ ] An old-format fixture (copy a real current file into `tests/fixtures/`) loads, and `migrate` fills defaults
- [ ] Unknown extra fields are ignored
- [ ] Creating a project with an existing slug does not overwrite it
- [ ] Top-bar totals are the same before saving and after loading (recomputed, not stored)
